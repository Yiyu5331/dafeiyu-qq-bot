# 11 · 逐条命令清单（照抄版）

这一章是「不想读解释、只想照着敲」的版本。

**规则**：
- 一条一条执行，每条后面都有「成功是什么样」
- 顺序不能乱（尤其 4 之后才能做 5）
- 报错就跳到该条下面的「卡住了怎么办」

> 全程以 macOS 为例。Windows 把 `~/` 换成 `C:\Users\你\`，`bash` 相关命令换成对应 PowerShell 写法。

## 第 1 步：装基础软件

| # | 命令 | 成功是什么样 |
|---|---|---|
| 1.1 | `xcode-select --install` | 弹窗点安装，装完 `git --version` 有输出 |
| 1.2 | `git --version` | `git version 2.x` |
| 1.3 | `curl -LsSf https://astral.sh/uv/install.sh \| sh` | 末尾提示 `installed to ~/.local/bin` |
| 1.4 | `source ~/.zshrc` 或重开终端 | `uv --version` 有输出 |
| 1.5 | `brew --version` | 有版本号；没有就先装 Homebrew |
| 1.6 | `brew install ffmpeg node` | `ffmpeg -version`、`node -v` 都有输出 |
| 1.7 | `python3 -V` | `Python 3.1x` |

**卡住了怎么办**

- `uv: command not found` → PATH 没生效，`export PATH="$HOME/.local/bin:$PATH"`，再 `uv --version`
- `brew` 装很慢 → 换源或挂代理；ffmpeg 只是备用，卡住可以先跳过
- `python3` 是 2.7 → 装 `brew install python@3.12`，后面用 `python3.12`

## 第 2 步：克隆 QQ 并注入 NapCat

| # | 命令 | 成功是什么样 |
|---|---|---|
| 2.1 | `ls /Applications \| grep -i qq` | 看到 `QQ.app` |
| 2.2 | `cp -R /Applications/QQ.app /Applications/QQ-test-mas.app` | 无报错，`ls -d /Applications/QQ-test-mas.app` 存在 |
| 2.3 | 下载 NapCat release，解压到 `~/napcat` | `ls ~/napcat` 有 `napcat.mjs` 或启动脚本 |
| 2.4 | 启动 NapCat（注入） | 终端出现日志，QQ 被拉起来 |
| 2.5 | 打开 `http://127.0.0.1:6099` | 出现 NapCat WebUI 登录页 |
| 2.6 | 用 `webui.json` 里的 token 登录 | 进得去，能看到「二维码」入口 |
| 2.7 | 手机 QQ 扫二维码 | 小号登录成功，WebUI 显示在线 |

**查看 token**

```bash
cat "$HOME/Library/Application Support/QQ/NapCat/webui.json"
```

**卡住了怎么办**

- 注入后 QQ 白屏 → 你注入了原版 `/Applications/QQ.app`，改用副本
- 6099 打不开 → QQ 副本没起来；或 host 不是 `127.0.0.1`
- 二维码扫了没反应 → 过期了，刷新重生成（60–180 秒）
- 「签名错误」→ 副本签名被破坏，删掉副本重新 `cp -R` 再注入

## 第 3 步：装 AstrBot

| # | 命令 | 成功是什么样 |
|---|---|---|
| 3.1 | `git clone https://github.com/AstrBotDevs/AstrBot.git ~/AstrBot` | 目录存在 |
| 3.2 | `cd ~/AstrBot` | — |
| 3.3 | `uv sync` | 末尾 `Installed xxx packages`，无红色报错 |
| 3.4 | `nohup .venv/bin/python3 main.py > /tmp/astrbot.log 2>&1 &` | 命令立即返回，给出 PID |
| 3.5 | `sleep 20 && curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:6185` | 输出 `200` |
| 3.6 | 浏览器开 `http://127.0.0.1:6185` | 出现登录页 |

**初始账号密码**：AstrBot 首次运行会在日志里打印默认账号密码，或者直接写进 `data/cmd_config.json` 的 `dashboard` 段。进去第一件事：**改密码**。

```bash
grep -A5 '"dashboard"' ~/AstrBot/data/cmd_config.json
```

**卡住了怎么办**

- `uv sync` 卡住 → 换 pypi 源（`uv sync --index-url https://pypi.tuna.tsinghua.edu.cn/simple`）
- 6185 没响应 → `tail -50 /tmp/astrbot.log` 看报错；常见是端口被占，改端口后重启
- 登录页打不开但日志正常 → 换浏览器 / 清缓存

## 第 4 步：两边连起来

| # | 命令 | 成功是什么样 |
|---|---|---|
| 4.1 | 生成 token：`python3 -c "import secrets;print(secrets.token_hex(16))"` | 得到 32 位十六进制 |
| 4.2 | AstrBot 后台 → 平台适配器 → 加 `aiocqhttp`，填 `127.0.0.1` / `6199` / token | 保存成功 |
| 4.3 | NapCat WebUI → 网络配置 → 新建 WebSocket 客户端，URL `ws://127.0.0.1:6199/ws`，token 同上 | 保存后状态变「已连接」 |
| 4.4 | `lsof -nP -iTCP:6199 -sTCP:LISTEN` | 有一行 AstrBot 在监听 |
| 4.5 | `tail -f /tmp/astrbot.log` 然后在手机发一句 | 日志出现 `FriendMessage` |

**卡住了怎么办**

- NapCat 一直重连 → token 不一致，或 AstrBot 没起
- 日志有事件但机器人不回 → 第 5 步的 provider 没配好
- 日志里 `whitelist` 拦截 → 第 7 步的白名单写错了

## 第 5 步：三个 provider

| # | 命令 | 成功是什么样 |
|---|---|---|
| 5.1 | DeepSeek key：platform.deepseek.com → API keys → 新建 | 得到 `sk-` 开头字符串 |
| 5.2 | AstrBot → 服务提供商 → 新建 OpenAI 兼容，base `https://api.deepseek.com/v1`，model `deepseek-flash`，key 填入 | 点「测试」通过 |
| 5.3 | 火山引擎控制台 → 语音 → 音频生成（Seed Audio）→ 创建应用 | 得到 APP ID + Access Token |
| 5.4 | AstrBot → 新建 `seed_audio_tts` provider，填 APP ID / Token / 参考音 | 测试能合成一段语音 |
| 5.5 | 硅基流动 → API keys → 新建 | 得到 `sk-` 开头字符串 |
| 5.6 | AstrBot → 新建 `openai_embedding`，base `https://api.siliconflow.cn/v1`，model `BAAI/bge-m3` | 测试通过 |
| 5.7 | `curl -s https://api.siliconflow.cn/v1/embeddings -H "Authorization: Bearer $SF_KEY" -H "Content-Type: application/json" -d '{"model":"BAAI/bge-m3","input":"测试"}'` | 返回 JSON 里有 1024 维向量 |

**卡住了怎么办**

- DeepSeek 401 → key 错或欠费
- 豆包 `401 code 45000010` → APP ID 和 Token 不匹配，多半是复制时带了整行说明文字
- 硅基流动 403 → key 权限不对；embedding 不需要实名
- 「模型不存在」→ 模型名大小写错了，`BAAI/bge-m3` 一个字都不能差
