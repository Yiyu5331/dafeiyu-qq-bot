# 09 · 运维与排障

这一章是「装完之后」的事：进程怎么守、日志在哪、掉线怎么办、坏了怎么恢复，以及**我真实踩过的 12 个坑**。

## 9.1 三个进程，三份日志

| 进程 | 作用 | 日志 | 启动 |
|---|---|---|---|
| QQ 副本 + NapCat | 连 QQ 服务器，收发消息 | NapCat 终端 / `webui` 里的日志页 | 双击 App 或 `QQ --no-sandbox -q <小号>` |
| NapCat 本体 | 注入后的运行时 | 终端输出 | 随 QQ 起来 |
| AstrBot | 大脑 | `nohup ... > /tmp/astrbot.log` | `cd ~/AstrBot && nohup .venv/bin/python3 main.py > /tmp/astrbot.log 2>&1 &` |

**记住一句话：谁不收消息，先看谁没在跑。**

```bash
# 三个都在吗
ps aux | grep -E "AstrBot|NapCat|QQ-test" | grep -v grep

# AstrBot 活着的标志
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:6185   # 期望 200

# 反向 WS 端口有人听吗
lsof -nP -iTCP:6199 -sTCP:LISTEN
```

## 9.2 QQ 掉线了怎么办

掉线是常态，NapCat 是注入方案，QQ 改协议就掉。

**正常掉线**（网络抖、电脑睡眠）：
1. 打开 QQ 副本，正常登录（一般还在线）
2. 如果提示扫码：**扫一次就行**，不用重装

**进程死了**（日志里看到 `Worker进程意外退出`）：
```bash
# 免扫码重登（macOS）
/Applications/QQ-test-mas.app/Contents/MacOS/QQ --no-sandbox -q <小号QQ号>
```
`-q` 会带上次的登录态，能省掉一次扫码。我掉线十几次，只有两次真的需要重扫。

**真的需要重扫时**：NapCat WebUI → 二维码 → 手机 QQ 扫。扫完别急着关窗口，等 10 秒看日志有没有 `登录成功`。

## 9.3 消息不进来了，按这个顺序查

1. **QQ 在线吗** → 用手机给这个号发一条，看 QQ 副本窗口有没有收到
2. **NapCat 连上了吗** → WebUI 首页的「已连接」状态
3. **AstrBot 收到事件了吗** → `tail -f /tmp/astrbot.log`，搜 `FriendMessage` / `aiocqhttp`
4. **被白名单拦了吗** → 日志里搜 `whitelist` / `拦截`
5. **provider 报错了吗** → 搜 `Error` / `401` / `timeout`

**90% 的情况是第 2 步**：NapCat 没连上 AstrBot。重开后端 + 重连即可。

## 9.4 备份与恢复

要备份的只有两样：

| 路径 | 内容 |
|---|---|
| `~/AstrBot/data/` | 配置、人格、记忆库（`data_v4.db`）、插件配置、插件数据 |
| 你的 key 文件 | 不要放在仓库里，单独放一个目录 |

```bash
cd ~/AstrBot
tar -czf ~/astrbot-backup-$(date +%m%d).tgz data \
  --exclude='data/attachments/*' --exclude='data/plugin_data/meme_manager/packs/*'
```
> 表情包目录几百 MB，**别打进备份**，重装后重新下就行。

恢复：解压覆盖 `data/`，重启 AstrBot。人格、记忆、插件配置全回来。

## 9.5 我踩过的 12 个坑

### ① 解压报「磁盘空间不足」，其实不是磁盘问题
macOS 上 `unzip` 解某些包会因扩展属性报错，错误信息误导。用 `ditto -x -k` 或 `tar` 解。

### ② 注入后 QQ 白屏
直接对 `/Applications/QQ.app` 注入破坏了签名。**必须克隆副本**（见 docs/02）。

### ③ NapCat WebUI 打不开 6099
qq 副本没起来，或 `webui.json` 里 host 是 `0.0.0.0` 而你访问了别的主机名。改 `127.0.0.1`。

### ④ 二维码扫了没反应
二维码 60–180 秒过期。刷新 WebUI 重新生成，别扫旧图。

### ⑤ NapCat 连不上 AstrBot（最常见）
- AstrBot 的 `ws_reverse_port`（6199）和 NapCat 里填的**反向 WS 地址必须一致**
- token 两边必须一致（AstrBot 的 `ws_reverse_token` = NapCat 的 `token`）
- 先起 AstrBot，再起 NapCat

### ⑥ 豆包语音 401 `code 45000010 request and grant appid mismatch`
APP ID 和 Access Token 不匹配 —— 90% 是从文档 / 记事本复制时把整行（含说明文字）复制进去了。**一个文件里只放一个值，冒号后面别带说明**。

### ⑦ 语音三条里才一条
`seed_audio_reply_probability` 默认 0.33（掷骰子）。想全语音就设 1.0；但**别一直 1.0**，耗钱且不自然。

### ⑧ 语音音色「跑偏」
豆包是音频生成模型，靠参考音模仿，**逐句合成会漂**。做法：整篇一次合成，参考音用 8–15 秒干净人声，再统一音量。

### ⑨ 表情包发出去是黑的
表情包很多是**黑底透明 gif**，QQ 某些客户端把它当不透明。塞进白底卡再发。

### ⑩ 白名单写对了还是被拦
格式是 `qq:FriendMessage:<QQ号>`（平台:消息类型:ID），少一段就匹配不上。群聊是 `GroupMessage`。

### ⑪ 改了配置不生效
AstrBot 有内存缓存 + `.bak` 自动备份。改完 `cmd_config.json` 要**重启**；WebUI 里改的则以 DB 为准，两边不一致时看日志。

### ⑫ 后台密码忘了
`data/cmd_config.json` 里 `dashboard` 段有用户名和密码 hash。忘了就删掉 `dashboard` 段重启，会回到默认账号；或者直接改 hash。

## 9.6 每天 30 秒的自检

```bash
curl -s -o /dev/null -w "AstrBot:%{http_code}\n" http://127.0.0.1:6185
lsof -nP -iTCP:6199 -sTCP:LISTEN >/dev/null && echo "WS:OK" || echo "WS:DOWN"
tail -50 /tmp/astrbot.log | grep -iE "error|401|timeout" | tail -3
```

三个都正常，就不用管它了。
