# 05 · 接三把 key：对话 / 声音 / 记忆

三把 key 各管一件事，缺一个也能跑，但会缺一块：

| key | 管什么 | 缺了会怎样 |
|---|---|---|
| DeepSeek | 说话 | 完全不回 |
| 豆包 Seed Audio | 声音 | 只回文字 |
| 硅基流动 bge-m3 | 记忆 | 记不住前天聊过什么 |

---

## 5.1 DeepSeek（嘴）

### 申请

platform.deepseek.com → API keys → 创建。格式 `sk-` 开头。

### 后台配置

服务提供商 → 新建 → 类型选 `OpenAI 兼容`：

| 字段 | 值 |
|---|---|
| id | `deepseek` |
| 类型 | `openai_chat_completion` |
| API Base | `https://api.deepseek.com/v1` |
| API Key | 你的 key |
| 模型 | `deepseek-flash` |

> 为什么用 flash：快、便宜，聊天场景够用。要更聪明换 `deepseek-chat`，贵一倍左右。

### 验证

后台「服务提供商」里点测试，返回 200 且有回复就通了。

---

## 5.2 豆包 Seed Audio（声音）

### 它是什么

不是普通的 TTS，是**音频生成模型**：给它一段参考音 + 一句话，它「模仿」出这句话。

所以：

- 好处：有气声、有情绪，不像念稿
- 坏处：**每次音色会漂**（同一个人两次说话音高能差 8%）

### 申请

火山引擎控制台 → 语音技术 → 音频生成（Seed Audio 1.0）→ 创建应用

拿到两个东西：

- **APP ID**（一串数字）
- **Access Token**

### 准备参考音

- 8–15 秒，纯人声，无背景音乐
- 内容随意（说一段话就行）
- 建议 `mp3` / `wav`，单声道

### 后台配置

服务提供商 → 新建 → 类型选 `Seed Audio TTS`：

| 字段 | 值 |
|---|---|
| id | `voice` |
| 模型 | `seed-audio-1.0` |
| APP ID | 你的 APP ID |
| Access Token | 你的 token |
| 参考音 | 上传那段 8–15 秒 |
| 整段合成 | **开启**（关键） |
| 触发概率 | `0.33`（三条里一条带语音） |

### 两个必须知道的点

1. **整段合成必须开**。逐句合成会逐句漂，一句一个音色。
2. **概率是掷骰子**。设 0.33 意味着大部分时候只发文字，这是正常的，不是坏了。

### 常见错误

```
HTTP 401 code 45000010 request and grant appid mismatch
```

意思是「你给的 APP ID 和 token 不是一对」。90% 的原因是从文件读 key 时**把整行读进去了**（比如 `- 豆包语音.txt：APP ID: 7994241122` 整行当成了 ID）。

正确做法：文件里只放值，一行一个：

```
APP ID: 7994241122
Access Token: xxxxxxxx
```

## 5.3 硅基流动 bge-m3（记忆）

### 它是什么

长期记忆不是「把聊天记录塞进 prompt」，而是：

1. 每句话 → 变成向量（embedding）
2. 存进向量库
3. 下次对话 → 把当前问题也变向量 → 找最像的几条 → 塞回 prompt

`bge-m3` 就是那个「变向量」的模型。

### 申请

siliconflow.cn → API 密钥 → 新建。格式 `sk-` 开头。

### 后台配置

服务提供商 → 新建 → 类型选 `Embedding`：

| 字段 | 值 |
|---|---|
| id | `memory` |
| 类型 | `openai_embedding` |
| API Base | `https://api.siliconflow.cn/v1` |
| API Key | 你的 key |
| 模型 | `BAAI/bge-m3` |
| 维度 | `1024` |

然后把「记忆插件」（`livingmemory`）的 `embedding_provider_id` 指向它。

### 验证

```bash
curl https://api.siliconflow.cn/v1/embeddings \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"BAAI/bge-m3","input":"今天好累"}'
```

返回里 `data[0].embedding` 有 1024 个数，就对了。

## 5.4 key 放哪

```
secrets/
├── deepseek.txt        # 一行 sk-xxx
├── 豆包语音.txt         # APP ID / Access Token 两行
├── 硅基流动.txt         # 一行 sk-xxx
└── 机器人凭据.txt       # 后台地址/账号/密码、NapCat token、OneBot token
```

`secrets/` 一定要在 `.gitignore` 里。**任何人拿到这个目录就等于拿到你的号。**

## 5.5 三把 key 一起验证

```bash
bash scripts/check_env.sh --keys
```

会分别打一次 DeepSeek、嵌入、语音接口，告诉你哪把有问题。
